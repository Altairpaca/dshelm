# Support and community channels

Use the narrowest channel that matches the problem. This keeps reproducible bugs, design discussion, upstream DSH questions, and security reports from being mixed together.

| Need | Where to go |
| --- | --- |
| Reproducible DSHelm bug | [Bug report](https://github.com/Altairpaca/dshelm/issues/new?template=bug_report.yml) |
| Installation / platform evidence | [Install report](https://github.com/Altairpaca/dshelm/issues/new?template=install_report.yml) |
| Real routing scenario or model-selection evidence | [Routing scenario](https://github.com/Altairpaca/dshelm/issues/new?template=routing_scenario.yml) |
| Feature proposal | [Feature request](https://github.com/Altairpaca/dshelm/issues/new?template=feature_request.yml) |
| Usage question, design discussion, or idea that is not yet a scoped bug/feature | [DSHelm Discussions](https://github.com/Altairpaca/dshelm/discussions) |
| Question about DSH public interfaces or runtime behavior | [DeepSeek Harness Discussions](https://github.com/deepseek-ai/deepseek-harness/discussions) |
| Security vulnerability | [`SECURITY.md`](SECURITY.md) |

## Before opening an issue

Search existing Issues and Discussions first. Include the DSHelm commit/version, DSH version, platform, minimal reproduction, and a redacted Resolution Trace or log when relevant. Do not post tokens, cookies, account identifiers, private repository names, or sensitive local paths.

## Scope and response expectations

DSHelm is an alpha project maintained on a best-effort basis. There is no guaranteed response or fix SLA. Maintainers prioritize reproducible defects, release blockers, compatibility evidence, and changes that preserve the Core / DSH boundary documented in [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).
