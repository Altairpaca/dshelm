## 1.1 Product definition (corrected this round)

**DSHelm Project** = an OmO-inspired, batteries-included agent distribution for
DeepSeek Harness. **DSHelm Core** = policy / configuration / routing kernel
(roles, categories, model profiles, deterministic resolution, runtime capability
validation, provenance traces, configuration/observability surfaces).

DSHelm is NOT a DSH fork, NOT another agent loop, NOT another AgentTeams, NOT a
700-plugin collection. Execution is COMPOSED from DSH-native primitives and mature
ecosystem capabilities (dsh-agent-teams, workflow plugins, fallback/router plugins)
wherever they exist. A feature visible to users (e.g. Teams) is not proof DSHelm
must reimplement its runtime.

Community reuse rule (before any new capability):
1. DSH core already provides it? 2. Mature DSH plugin? 3. AgentTeams/workflow/fallback/router?
4. Oh-My-DSH (capability catalog / research corpus / reference only — never wholesale dependency)?
5. Only a real gap justifies own implementation. Do NOT reimplement mailbox/team state;
   DSHelm policy → AgentTeams adapter/backend is the direction.

   (exactOptionalPropertyTypes) — guard before spread.

   zod `.optional()` output (`T | undefined`) mismatches exact-optional interfaces → type the
   schema as `z.ZodType<ControlPlaneProjectionValue>` (variance-only cast; runtime `parse`
   stays the gate).
