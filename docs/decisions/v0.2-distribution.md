## 3. Product definition (unchanged from v0.1)

- DSHelm = opinionated integrated agent distribution; DSH = runtime/kernel.
- DSHelm Core = policy/routing/capability/provenance kernel.
- DSHelm is NOT: model router only, policy resolver only, WebUI only, a
  Sisyphus preset, an AgentTeams clone, or a plugin catalog.
- Success experience: "install DSHelm and bare DSH immediately becomes a
  complete, configurable, observable, heterogeneous-model, multi-agent
  coding-agent environment."
- Competitive edge: composition, compatibility, verification,
  observability, migration, opinionated defaults — NOT raw feature count.
- Community reuse rule: 80%-correct mature implementation → adapter +
  upstream improvement, never a 100% rewrite.

## 4. Hard boundaries

- Do not reimplement: generic agent loop, session runtime, generic workflow
  engine, team mailbox, task DAG persistence, subagent runtime, provider
  transport, Cordis, terminal infrastructure.
- Do not copy restricted source (OmO SUL-1.0; unlicensed Oh-My-DSH content)
  into Apache-2.0 DSHelm. Behavioral compatibility ≠ source copying.
- Third-party absorption requires a ledger entry:
  `docs/ecosystem/source-ledger.md` (repo, commit, license, files, purpose,
  modification, attribution).
- Every P0 contract from v0.1 stays: runtime validation, determinism,
  provenance, request/header evidence, license clarity.
- main is never force-pushed; merged history is never rewritten; unique
  commits are never deleted; no secrets/credentials in the repo.
